## Package engineering (do not re-litigate per PR)

### Migrations

- Additive dated migration files are correct for 7.1+. The single consolidated create migration was right for the **7.0 clean break** only.
- Hosts run only pending migrations via `canvas:migrate` / `migrate`. Multiple files are normal package practice (Cashier, Spatie, etc.).
- Never edit migrations already on `develop` / Packagist for this major.
- Channel “one clean schema” energy into small, boring migrations — not squashing.

### Scheduled work (`canvas:digest` pattern)

- Artisan command + Laravel scheduler **is** The Laravel Way. Keep commands even if humans rarely type them day to day.
- Operators re-run after outages; `schedule:list` stays readable; tests invoke the command.
- Prefer `Schedule::command('…')` over opaque closures for package surfaces.
- Use the same pattern for publish-announce and webhook-delivery prune.

### `mail.enabled` vs per-user `digest`

- **Both layers stay:** install kill-switch (`CANVAS_MAIL_ENABLED` / `mail.enabled`) + user opt-in (`canvas_users.digest`).
- Config = host capability (staging must not email; hosts without mailers); user flag = preference.
- Command respects both (schedule only if enabled; recipients only if `digest = true`).
- Naming is slightly awkward (`mail.enabled` only gates digest). **Do not rename in 7.1** unless a dedicated tiny PR is requested.

## PR1 — Scheduled → live announcements

**Goal:** When `published_at` crosses “now”, fire the same domain events / webhooks as a human moving scheduled → live, **without double-firing**.

**Why first:** Delivery history and calendar “went live” stories are incomplete without this.

### Scope

- [x] Design idempotent selection (pick one and stick to it):
    - [x] **Option A (preferred if simple):** `published_notified_at` (or similar) on `canvas_posts`, set when announce succeeds
    - [ ] **Option B:** watermark / last-run cursor in settings or cache (must be multi-server safe)
- [x] Additive migration if a column is required
- [x] Artisan command (name TBD, e.g. `canvas:publish-scheduled` or `canvas:announce-scheduled`)
- [x] Register on the Laravel scheduler (every minute; tiny indexed query)
- [x] Reuse `PostLifecycle` / `PostLifecycleEvents` — single source of classification (`scheduled → live` → `PostPublished`)
- [x] Do not rewrite public content columns for visibility (already time-based); only announce + marker
- [x] Pest: fires once; no double fire on subsequent runs; draft/live ignored; `published_at` edge cases
- [x] Update `docs/webhooks.md` (remove “does not fire when time passes”; document scheduler)
- [x] Update `docs/content.md` and/or `docs/installation.md` if host-visible
- [x] `composer pint:test` + `composer lint` + filtered Pest green

### Non-goals

- Changing how `published()` scope works
- Auto-promoting `pending` JSON when the schedule elapses
- A config kill-switch for this command (always register; work is cheap)

### Acceptance

- [x] Schedule a post slightly in the future; after the command runs, `PostPublished` / `post.published` path fires once (assert events/jobs in tests)
- [x] Second run does not emit again
- [x] Host docs match behavior

### Handoff pointers

- `src/Support/PostLifecycle.php` — `scheduled → live` already classified
- `src/Support/PostLifecycleEvents.php`
- `src/CanvasServiceProvider.php` — `registerScheduler()` (digest pattern)
- `docs/webhooks.md` — current caveat to replace

## PR2 — Webhook delivery history + retry

**Goal:** Admins can see recent outbound deliveries, inspect failure signals, and retry failed ones. Failures are no longer “queue log only.”

### Scope — data plane

- [x] Migration: `canvas_webhook_deliveries` (name flexible)
    - [x] `id` (UUID; align with `Canvas-Delivery-Id` where possible)
    - [x] `event` (string)
    - [x] `url` (no credentials; never store the signing secret)
    - [x] `status`: pending / success / failed
    - [x] `http_status` nullable
    - [x] `attempt` / `attempts`
    - [x] Payload snapshot **size-capped** (payloads are metadata-only today — OK to store)
    - [x] `response_body` size-capped (e.g. 2–8KB)
    - [x] `error_message` nullable
    - [x] `post_id` nullable (index; FK optional)
    - [x] timestamps (`created_at`, optional `finished_at`)
- [x] Model + factory
- [x] Instrument `DispatchOutboundWebhooks` to create a pending row
- [x] Instrument `DeliverWebhookJob` for success / final failure (per-attempt updates optional but useful)
- [x] Never log or persist webhook **secrets**

### Scope — admin API + UI

- [x] Gate: same as integrations (`manage-integrations`)
- [x] List recent deliveries (paginate or last N); filter by status/event is nice-to-have
- [x] Detail: event, times, HTTP status, truncated response, delivery id
- [x] **Retry** failed delivery: new signed POST, **new delivery id**, keep original row for audit
- [x] SPA: Webhooks area on Integrations (drawer section or sub-panel) — match existing patterns
- [x] i18n: `en` first, then every locale

### Scope — retention

- [x] Prune rows older than **30 days** (default)
- [x] Artisan command e.g. `canvas:prune-webhook-deliveries` and/or weekly schedule
- [x] Document retention in `docs/webhooks.md`

### Scope — quality

- [x] Pest: success logged; failure logged; retry creates new delivery; prune
- [x] Vitest for non-trivial UI helpers
- [x] `docs/webhooks.md`: history, retry, queue + scheduler reminders
- [x] `npm run typecheck && npm run lint && npm test` as needed
- [x] `npm run build` + commit `resources/dist/` if SPA changed
- [x] `composer pint:test && composer lint` + Pest (filtered, then broader as appropriate)

### Non-goals

- Multiple webhook endpoints / per-event URLs
- Storing full post HTML body in payloads
- Inbound webhooks
- Full analytics dashboard

### Acceptance

- [x] Publish/update/delete path creates delivery rows
- [x] Failed remote (non-2xx) visible as failed after retries exhaust (document if per-attempt rows differ)
- [x] Admin can retry and see a new delivery
- [x] No secrets in DB rows or API JSON

### Handoff pointers

- `src/Jobs/DeliverWebhookJob.php`
- `src/Listeners/DispatchOutboundWebhooks.php`
- `src/Http/Controllers/IntegrationsController.php`
- `resources/js/pages/Integrations/`
- Single endpoint still lives in `canvas_settings`

## How to use

1. Use a **real host** (or install-smoke / e2e host), not only Orchestra Testbench.
2. Prefer a host with **scheduler + queue** configured the way production will run:
    - `php artisan schedule:run` every minute (or `schedule:work` in dev)
    - `queue:work` if `QUEUE_CONNECTION` is not `sync`
3. Work **top to bottom** within each section. Check boxes only after you personally verify.
4. When a workstream ships, **add or un-stub** steps in that PR’s section in the same change set when practical.
5. Automated Pest/Vitest/Playwright still run in CI — this list is **human confidence**, especially multi-minute scheduling and UI feel.

## PR1 — Scheduled → live announcements

**Goal:** A scheduled post becomes public by time **and** fires `PostPublished` / `post.published` once, without reopening the editor.

### Setup

- [ ] Admin → Integrations → Webhooks: HTTPS URL, subscribe at least to **Published** (`post.published`), secret saved
- [ ] Confirm host will run `canvas:announce-scheduled` (scheduler every minute; `php artisan schedule:list` shows it)

### Happy path (time elapsed)

- [ ] Create a post, set `published_at` **1–2 minutes in the future**, save (scheduled)
- [ ] Confirm outbound **scheduled** signal if subscribed (`post.scheduled` / your listener) — optional but good
- [ ] **Do not** open the editor again before the time passes
- [ ] After `published_at`, confirm the post is already in the public/query sense (`published()` / your front end) without a save
- [ ] Within ~1–2 scheduler ticks, confirm **published** fires once:
    - [ ] Webhook receiver got `post.published` (or domain listener / log)
    - [ ] Only **one** delivery for that go-live (wait another minute; no duplicate)
- [ ] Optional: `php artisan canvas:announce-scheduled` manually after time passes — still only one announce if the scheduler already ran

### Human publish still works

- [ ] Draft → set `published_at` to now/past → save → `post.published` immediately (no wait for poller)
- [ ] Scheduled post → change `published_at` to past in editor → save → `post.published` immediately
- [ ] Subsequent scheduler ticks do **not** send a second `post.published` for that post

### Negatives

- [ ] Pure draft (no `published_at`) never gets `post.published` from the announce command alone
- [ ] Still-future scheduled post does not get `post.published` early
- [ ] Unpublish (clear `published_at`) → reschedule future → when it goes live again, you get a **new** published announce (marker cleared on leave-live)

### Docs sanity (quick)

- [ ] [webhooks.md](./webhooks.md) no longer claims time-elapsed skips `PostPublished`
- [ ] [configuration.md](./configuration.md) / [installation.md](./installation.md) mention `canvas:announce-scheduled`

## PR2 — Webhook delivery history + retry

**Goal:** Admin can see recent outbound deliveries, inspect failure signals, and retry failures.

### Happy path

- [ ] Admin → Integrations → Webhooks enabled (HTTPS URL + events + secret)
- [ ] Publish / schedule / update / delete a post (or **Send test**)
- [ ] Webhooks detail page **Recent deliveries**: new row appears (refresh if needed)
- [ ] Successful remote: status **Success** + HTTP 2xx
- [ ] Force failure (receiver returns 5xx, or temporary bad endpoint): after queue retries exhaust, row shows **Failed** with error / response snippet
- [ ] **Retry** on failed row → new delivery id appears as Pending/Success; original failed row remains
- [ ] Expand a row: delivery id, URL, error/response visible; **signing secret never** in UI or network JSON
- [ ] Status / event filters narrow the list; empty filtered state is calm (not “no deliveries ever”)

### Retention

- [ ] `php artisan schedule:list` shows `canvas:prune-webhook-deliveries` (weekly)
- [ ] Optional: create an old fixture row and run `php artisan canvas:prune-webhook-deliveries --days=30` — old row gone
- [ ] [webhooks.md](./webhooks.md) documents history, retry, and 30-day retention

## PR3 — Publishing calendar

**Goal:** Month view of scheduled + already published posts; scope respects roles.

### Happy path

- [ ] Sidebar (and command palette) shows **Calendar** → `/calendar`
- [ ] Month header: prev / next / **Today**; title matches the selected month
- [ ] Focus the grid and use ← / → to change months; Escape clears a selected day
- [ ] Seed a mix: past `published_at` + future scheduled in the current month
- [ ] Grid cells show chips (sm+); **scheduled** reads blue-ish, **published** green-ish (distinct); mobile uses status dots
- [ ] Days outside the month are muted but still clickable if they have posts from the padded range
- [ ] Click a day with posts → panel lists them with time, author (if present), status badge
- [ ] Click a post row → editor opens for that id
- [ ] Click the same day again (or navigate months) clears/resets day selection sensibly
- [ ] Empty month (no published/scheduled in-month): calm empty state + new-post CTA
- [ ] Pure drafts never appear on the grid

### Scope / roles

- [ ] As **Admin/Editor**: Mine vs All authors pill; All shows other authors’ posts
- [ ] As **Contributor**: no scope pill (or forced mine); `?scope=all` still only own posts
- [ ] Contributor cannot open another author’s post from calendar deep-link beyond normal post policy
- [ ] Dashboard pipeline **View all** on Scheduled lands on `/calendar` (not drafts tab)
- [ ] Posts **Drafts** tab shows **View calendar** link

### Negatives

- [ ] No drag-and-drop reschedule UI
- [ ] Invalid API range (missing `from`/`to`, inverted, >92 days) returns 422 if you probe the JSON API
- [ ] Month far in the past/future with no content still loads without error

## PR4 — Revisions finish line

> **Status:** implemented on develop.

**Goal:** Version history feels finished: documented, bounded, labeled, restore-safe.

### Baseline

- [ ] Open a post → publish or update → open **Version history** → list shows checkpoints
- [ ] Each row secondary line shows a **reason** (Published, Updated, Left editor, …) when recorded
- [ ] Restore a **draft** revision → editor public fields update; a new Restored checkpoint appears
- [ ] Restore onto a **live** post → content lands in **pending**; public columns unchanged until Update
- [ ] Leave the editor with changed draft content → leave checkpoint appears (or is skipped if content matches latest)
- [ ] Rename a version → Named filter finds it; primary label is the name

### Retention

- [ ] `php artisan schedule:list` shows `canvas:prune-post-revisions` (weekly)
- [ ] Optional: create >50 factory revisions for one post and run `php artisan canvas:prune-post-revisions` — only newest 50 remain
- [ ] [content.md](./content.md) documents checkpoints, restore vs pending, and 50-per-post retention
- [ ] Public readers never join or expose `canvas_post_revisions`
